## 1. ① CLIP 接入 UI（完整模型 727MB）

### 1.1 能力拆分
- **A. 自动场景标签（零样本）**：导入索引后，对每张图用图像编码器取 embedding，与「预设场景标签集合」的 text embedding 算相似度，top-k 写入 tags（海边/雪山/会议/演讲/日落…）。
- **B. 自由中文语义搜索**：高级搜索 `text:` 走 CLIP 向量 top-k 检索（如「一张海边日落的照片」）。

### 1.2 模型打包（用户已选）
- 完整模型 = 图像编码器 333MB + 文本编码器 393MB = **727MB**，放 `models/clip/`。
- **分层加载**：仅在用户开启 CLIP 功能（设置开关）+ 实际调用时由 `ClipService` 延迟加载（已验证），不增加常驻内存。
- ARM（麒麟 aarch64）真机性能未知，**列为验收风险**，需真机实测首张耗时。

### 1.3 代码落点
| 文件 | 改动 |
|---|---|
| `core/clip.py` | 已落地；补「预设场景标签 embedding 缓存」与 `search_text(query, topk)` 接口 |
| `core/autotag.py` | CLIP 零样本替换路径/文件名关键词匹配；保留关键词作为兜底 |
| `core/pipeline.py` | 索引完成后触发 CLIP 场景标签生成（可后台、可跳过、可重试） |
| `core/search.py` | `text:` 语法路由到 CLIP 向量检索（已有 `text:` 关键词检索，新增向量分支） |
| `ui/library_bridge.py` | `text:` / 场景标签检索桥接；CLIP 开关与进度回调 |
| `ui/qml/components/AdvancedSearchPanel.qml` | 高级搜索增加「语义搜索」输入框（已支持 `text:` 语法，补 UI 入口） |
| `ui/qml/` 相关页 | 标签筛选支持场景标签展示 |
| 设置页 | 新增 CLIP 开关 + 首次索引提示（727MB 模型） |

### 1.4 验收
- `pm clip-index` / `pm clip-search` 仍可用（CLI 回归）。
- GUI：导入后场景标签出现；高级搜索 `text:` 返回合理结果。
- 单元测试 + `gui_check.py` 回归全绿；`--smoke` 通过。

## 2. ② 反向地理编码（按地名搜）

### 2.1 数据源（拍板：全球库）
- **默认**：**全球行政+城市库**（GeoNames `cities1000` 或 `cities5000` 级，约 13万~23万城市，公开数据集，离线打包进 `models/geo/`），覆盖海外旅拍。
- **中国细化**：在全局库基础上叠加**中国省/市/区行政中心 + 主要景点 POI**，使国内精度到区/景点级（全球库在国内城市级足够，区/景点靠中国数据补强）。
- 体积：全球城市库 + 中国细化约 **10–30 MB**（远小于 CLIP 模型，可接受）。
- 逆地理编码算法：经纬度 → KD-tree 最近邻 admin/城市中心点 → 返回「国家/州/省/市/区/景点名」层级字符串；稀疏区域回退到最近国家/州。

### 2.2 搜索入口
- 扩展 `gps:` 语法：除现有坐标/范围搜外，支持 `gps:北京` / `gps:西湖` → 解析为对应区域 bbox 再查。
- 地图页 `MapPage.qml`：点位 hover/点击显示反地理编码地名（替代纯坐标）。

### 2.3 代码落点
| 文件 | 改动 |
|---|---|
| `core/geocode.py`（新增） | 离线逆地理编码（KD-tree + 数据加载） |
| `core/search.py` | `gps:` 支持地名 → bbox |
| `ui/library_bridge.py` | 地名解析桥接 |
| `ui/qml/pages/MapPage.qml` | 点位显示地名 |
| `models/geo/`（新增） | 全球城市库（GeoNames）+ 中国省/市/区+景点细化数据（SQLite/CSV） |

### 2.4 验收
- `gps:北京` 返回北京区域内照片；地图点位显示「北京市/海淀区/西湖」等。
- 离线、无网络依赖；数据文件体积小。

## 3. ③ 照片堆叠 Stacks（合并浏览，不删）

### 3.1 检测规则（拍板）
- **连拍栈**：同目录 + 拍摄时间间隔 < 5 秒 + 内容相似（dHash 汉明距离 < 阈值但非「近似重复」级）。
- **双格式栈**：同 basename 的 RAW + JPG（如 `IMG_1234.CR3` + `IMG_1234.JPG`）。
- 与去重区分：去重=可删（近似重复）；堆叠=只合并浏览，**不触发任何删除**。

### 3.2 数据模型
- 新增 `stacks` 表（`id`, `representative_photo_id`）或 `photos.stack_id` 列；`stack_id` 为 NULL = 不在栈中。
- 代表帧默认显示；展开看全部成员。

### 3.3 代码落点
| 文件 | 改动 |
|---|---|
| `core/db.py` | 新增 `stacks` 表 / `photos.stack_id` |
| `core/stacks.py`（新增） | 扫描时检测连拍/双格式 → 建栈 |
| `ui/library_bridge.py` | 栈查询、展开/收起 |
| `ui/qml/pages/GalleryPage.qml` | 网格显示代表帧 + 栈角标；点击展开 |
| `ui/qml/components/` | 栈展开浮层 |

### 3.4 验收
- 连拍组在网格显示单张+角标；点击展开见全部。
- 原图不动、不产生删除；与去重页互不干扰。

## 5. 风险与待验证

- **CLIP 727MB 加载耗时 / ARM 真机性能**：Windows 已验证 11.8s 加载、0.52s/张（缩略图）；麒麟 aarch64 真机未测，列验收风险。
- **场景标签质量**：预设标签集需覆盖摄影师常用场景；badcase 用关键词兜底。
- **地理数据准确性**：全球城市级最近邻可靠；国内区/景点级靠中国细化数据补强；街道/门牌级不可达（可接受，摄影师按城市/景区整理足够）。GeoNames 数据需保留署名（AGPL/CC 兼容，离线打包注明来源）。
- **堆叠误判**：间隔阈值/相似度阈值需调参，避免把不同场景误并。
- **体积**：727MB 模型 + dist 成品增大；需重新打包并评估 trim 策略（CLIP 模型在 `models/`，trim_dist 不影响它）。
